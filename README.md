`movement-figures` makes reproducible figures and videos about the
[`movement` Python package](https://movement.neuroinformatics.dev/), for
papers, posters, talks, and social mediea. It produces two kinds of
output:

- **Figures**: static plots, each generated by a Quarto document under
  `figures/`. They are collected in a gallery published at
  [neuroinformatics.dev/movement-figures](https://neuroinformatics.dev/movement-figures/).
- **Videos**: animations made with [manim](https://www.manim.community/),
  each in its own folder under `videos/`.

Both build on the `movement_figures` Python package under `src/`,
which holds the shared visual style (colours, fonts, plotting configurations)
and reusable helpers, so all outputs look consistent.

## Setup

Requires [uv](https://docs.astral.sh/uv/). Clone the repo and install the
environment:

```bash
git clone https://github.com/neuroinformatics-unit/movement-figures
cd movement-figures
uv sync                # if working on figures only
uv sync --group video  # if working on videos too
```

Figures also need the [Quarto CLI](https://quarto.org/docs/get-started/).
Videos need a few more things, described under [Videos](#videos).

## Figures

Each figure is a self-contained Quarto document (`.qmd`) under `figures/`.
All figures share execution settings from `figures/_metadata.yml`, and are
assembled into a gallery via `index.qmd` and `_quarto.yml`.

To render the gallery locally, run:

```bash
uv run quarto preview                  # live-reload while authoring one figure
uv run quarto render                   # build all figures + the gallery
```

The gallery is written to `_site/`; open `_site/index.html` in a browser to
view it. Vector exports (`pdf` + `svg`) are written to `outputs/` and
committed; the gallery (`_site/`) and caches are not.

### Data sources

Figures may draw on two data sources:

- **movement sample data**: the primary source for most inputs, and the only
  option for large files (tracks, videos). Figures fetch these via
  [movement.sample_data](https://movement.neuroinformatics.dev/latest/api/movement.sample_data.html)
  in their code cells, and each `.qmd` declares its datasets in Quarto frontmatter:

  ```yaml
  sample_data:
    - filename: DLC_single-mouse_EPM.predictions.h5
      with_video: true
  ```

  The `prefetch-sample-data` helper reads these declarations and downloads
  everything up front, so a render finds the data already cached:

  ```bash
  uv run prefetch-sample-data
  ```

- **The `data/` folder in this repo**: for *small* files only (< 500 KB), such
  as the ROI coordinates. This folder is git-tracked, so anything large would
  bloat the repo. Access it from a figure via `movement_figures.data_dir()`.

### Adding a figure

- Copy an existing `.qmd` file in `figures/`.
- Pick a target `medium` for `apply_style`: `manuscript`, `poster`, or
  `presentation`.
- Adapt the `.qmd` frontmatter and code to fetch and process the data it
  needs and build the figure.
- End with `save_figure(fig, "<name>")`.
- Run `uv run quarto render` and inspect the new files in `outputs/`, or the
  whole gallery in `_site/index.html`.

## Videos

Each video lives in its own folder under `videos/`, with its manim scenes and
a `video.yml` describing how to build it. Building blocks shared between
videos are in `movement_figures.video`.

| Video | Description |
|---|---|
| [`videos/showcase`](https://github.com/neuroinformatics-unit/movement-figures/tree/main/videos/showcase) | A silent ~2 min looping promo |

Videos need manim, installed as an optional dependency group, plus ffmpeg and
pango/cairo on the system (e.g., on Ubuntu 24.04:
`sudo apt install ffmpeg libpango1.0-dev libcairo2-dev pkg-config`):

```bash
uv sync --group video
```
Each video needs files from its own `assets/` folder (`videos/<video>/assets`),
which is committed. Some inputs, such as third-party logos and large files,
can't be committed. You can put those in `videos/<video>/inputs/` before rendering
and declare them in the video's `video.yml` manifest alongside any files
you need to fetch from `movement`'s sample data.

The `movement-video` command checks the inputs and renders the video.
For example, to render the showcase video:

```bash
uv run movement-video check videos/showcase    # are all inputs in place?
uv run movement-video render videos/showcase   # 720p draft
uv run movement-video render videos/showcase --resolution 1080p  # 1080p final
```

Renders are written to the video's `media/` folder, which isn't committed.
Finished versions are tagged and published as GitHub Releases. Each video's
own README explains its content, inputs and how to make a new version.
For an example, see [`videos/showcase/README.md`](videos/showcase/README.md).

## Fonts

The fonts—Liberation Sans and Barlow are bundled under
`src/movement_figures/fonts/` and registered with matplotlib and manim
automatically. Both are licensed under the SIL Open Font License; see the
`LICENSE-*` files alongside them. The gallery and videos use them for all text,
so figures and videos look consistent no matter what fonts
are installed on your system.


## Development

Code quality is enforced with [ruff](https://docs.astral.sh/ruff/) (linting and
formatting), [codespell](https://github.com/codespell-project/codespell)
(spelling), and a set of [pre-commit](https://pre-commit.com/) hooks.

Install the git hook once, so the checks run automatically on every commit:

```bash
uv run pre-commit install
```

After that, committing runs the hooks against your staged files. To run every
hook across the whole repo on demand:

```bash
uv run pre-commit run --all-files
```

Generated figures under `outputs/` are deliberatley excluded from the hooks
so their committed vector files stay byte-stable across re-renders.

> [!note]
> `ruff` only lints `.py` files—the Python inside `figures/*.qmd` code cells is
> not checked for now. Keep figure code tidy by hand, or factor reusable logic
> into `src/movement_figures/` where it is linted.

Tests live in `tests/` and run with `uv run pytest`; tests that need manim
are skipped unless the `video` group is installed.

Every pull request re-renders the site as a CI check that all figures still
build, and every merge to `main` redeploys the gallery to GitHub Pages (see
`.github/workflows/render_and_deploy.yml`). Videos are not rendered on CI,
since their inputs aren't all in the repo.
